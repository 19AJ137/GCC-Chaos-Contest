# GCCカオス暗号の懸賞問題 ライトアップ — 鍵なしで内部状態を復元して平文を読むまで

- 対象: GCC6（Gao's Chaos Cryptosystem 6、1996 年）の `File_cryption` で作られた懸賞の暗号文 3 本（[`../ciphertext/`](../ciphertext/)）
- 範囲: 暗号文だけから、DLL の内部状態（鍵から作られる値の一式）を復元し、3 本を全バイト復号するまでの解き方。鍵（パスワード）の復元は、この文書のあとに行った。[password.md](password.md) を参照。
- 前提: GCC6 のアルゴリズム（[algorithm.md](algorithm.md)）
- コード: [`../src/keyless/`](../src/keyless/)（§16）。結果の確認は [`../src/verify.py`](../src/verify.py)

## 0. 要約

- 懸賞の暗号文 3 本（A・B・E）は、**2 つの鍵 k・v で 2 回暗号化**されていた。A と E は v → k の順、B は A と同じ平文を k → v の順。
- 解読はすべて鍵なしで行った。使ったのは、暗号文 3 本、暗号の仕組み（DLL の解析で分かっていたもの）、ベンダーの公開ページの文章（言語モデルの材料とクリブ）だけである。
- 道筋は次の 8 段。

| 段 | やったこと | 使ったもの | 得たもの |
|---|---|---|---|
| 1 | A⊕E の最上位ビットを読む（§3） | A・E | 外側の鍵の連鎖フラグ（一部の区間）と、説明のつかない 1 列 |
| 2 | その 1 列を「内側にもう 1 層ある跡」と読む（§4） | A・E | 二重暗号化という構造 |
| 3 | 2 層分の連鎖フラグと 2 本の平文を、言語モデルで同時に解く（§5） | A⊕E | 先頭 528 バイトの平文 2 本と、2 組の連鎖フラグ |
| 4 | B の形の候補を、鍵ストリームが消える恒等式でふるう（§6） | A・B と 3 の結果 | B は「同じ平文、鍵の順序が逆」 |
| 5 | A・B の式を連立させる（§7） | 同上 | 2 本の鍵ストリーム（118 語ずつ） |
| 6 | 鍵ストリームを写像の式に当てる（§8・§9） | 5 の結果 | 写像の定数と状態（倍精度で厳密）、先頭 1,024 バイトの平文 |
| 7 | 写像を逆向きにたどる（§10.1） | 6 の結果 | 空回しの前の初期値、IV の確定 |
| 8 | 1,024 バイトごとの作り直しを追う（§10.2〜§10.4） | 7 の結果と E | E の残り 314 バイト、鍵スケジュールの出力の一式 |

- 結果:
  - 平文は 3 本とも全部読めた（A・B は 1,024 バイト、E は 1,338 バイト。§12）。
  - 2 本の鍵それぞれについて、DLL が鍵から作る値（写像の番号、初期値、定数のもと、IV、空回しの回数）が分かった（§11）。この値から DLL の処理をなぞると、3 本が全バイト復号でき、B が 1 ビットも違わず作り直せる。
- 計算は 2 コアの計算機で足りた。いちばん重い段（§8.2 の写像 2）で十数分、ほかは数分以内。

## 1. 問題

- 懸賞の文面（`PRIZE.TXT`）: 「カオス インフォガード」で `contest.txt` の内容を解読できる暗号キーを探し、キーと平文を送る。1995 年 10 月に始まり、懸賞金は 1,000 万円、期限は 1997 年 12 月 31 日。未解読のまま終わったと発表されている。
- 手元にある懸賞の暗号文は 3 種類。

| 呼び名 | ファイル | 大きさ | ファイルの日付 | 入っていた配布物 |
|---|---|---|---|---|
| A | `ciphertext/A.bin` | 1,024 バイト | 1996-09-04 | 日本語 16bit 版（`software/Net9718.exe`） |
| B | `ciphertext/B.bin` | 1,024 バイト | 1996-10-20 以前（配布物は 1996-12-13） | 日本語 32bit 版（`software/net9729.exe`） |
| E | `ciphertext/E.bin` | 1,338 バイト | 1996-11-16 | 英語 16bit 版（`software/iisi9605.exe`） |

- 暗号は DLL（GCC6）の `File_cryption`。アルゴリズムは逆アセンブルで復元してあり、Python の再実装（[`../src/gcc6/gcc.py`](../src/gcc6/gcc.py)）が実物の DLL と全バイト一致する（[algorithm.md](algorithm.md)）。この文書では、そこは分かっているものとする。

## 2. GCC6 の仕組み（解読に要る分だけ）

以下、語 = 4 バイト（語 n はバイト 4n〜4n+3）。

### 2.1 鍵から作る値（鍵スケジュールの出力）

DLL は最初に鍵から次の値を作る。**このあと、鍵そのものは使わない。**

| 値 | 中身 |
|---|---|
| mode | 写像の番号（0・1・2） |
| k780・k788・k7b0・k7b8 | 0 以上 1 未満の倍精度の数（呼び名は DLL の変数の番地から） |
| S | 32 ビットの整数。連鎖の初期値 IV（S の 4 バイト）と、空回しの回数（S mod 79、最小 11）を決める |
| b0・b1 | 16 ビットの定数（別の 32 ビットの和 T の下位 16 ビット）。以下 lo と書く |

### 2.2 写像

倍精度の数の列を作る「カオス写像」が 3 種類ある。

| mode | 1 歩 | 定数 | 初期値 | 出力 |
|---|---|---|---|---|
| 0 | x ← (1 − x)·x·r | r = 3.9 + 0.1·k7b0 | x = k780 | x |
| 1 | y ← y² − p | p = 1.9 + 0.1·k7b0 | y = 2·k780 − 1 | (1 + y)/2 |
| 2 | u′ = A·u − Q·u·v、v′ = C·v + Q·u² | P = 0.9 + 0.4·k7b0、Q = 1.72 − 0.8·P − 0.14·k7b8、A = Q·P + 1、C = 1 − Q | u = k780、v = k788 | v′ |

- **1 歩ごとに、状態の倍精度表現の下位 16 ビットを lo に書き換える。** 定数（r、p、Q、A、C）の下位 16 ビットも lo にする。したがって、状態も定数も、自由なのは上位 48 ビットだけである。
- 初期値を作ったあと、空回しの回数だけ写像を進めてから、鍵ストリームを取り始める。

### 2.3 鍵ストリームと連鎖フラグ

語ごとに写像を 1 歩進め、出力の倍精度の 8 バイト（リトルエンディアンで b0〜b7）から

- **鍵ストリームの語 K = (b4, b2, b3, b5)**。仮数のビット 16〜47 の 32 ビットにあたる。
- **連鎖フラグ**: b6 > 0xE6 なら「連鎖なし」、そうでなければ「連鎖あり」。b6 は指数の下位と仮数の上位 4 ビットなので、出力の大きさで決まる。

を取る。出力のうち鍵ストリームに出ないのは、下位 16 ビット（lo に固定）と上位 16 ビット（符号・指数・仮数の上位 4 ビット）だけである。

### 2.4 暗号化の式（選んだ語だけ連鎖する）

レジスタ R（32 ビット、最初は IV）を持ち、語 n の入力を I_n、出力を O_n として

```
連鎖なしの語:  O_n = I_n ⊕ K_n
連鎖ありの語:  O_n = I_n ⊕ K_n ⊕ R、  R ← O_n（暗号化のとき。復号のときは R ← 入力の暗号文）
```

以下、f_n = 1 を「語 n は連鎖あり」、p(n) を「n の直前の連鎖ありの語」と書く。

### 2.5 1,024 バイトごとの作り直しと、端数

- `File_cryption` は 1,024 バイト（256 語）ごとに、**k7b0 の倍精度表現のバイト 5 を、その時点の R の 2 バイト目に置き換えて**定数を作り直し、**状態を初期値に戻す**（空回しはしない）。R は引き継ぐ。
- 4 バイトに満たない端数は、鍵ストリームをもう 1 語取り、バイトごとに c_j = m_j ⊕ K の j バイト目 ⊕ bl、bl ← c_j とする。bl の最初の値は IV の 2 バイト目。

### 2.6 解読の足がかりになる性質

1. ナンスも IV の乱数もない。同じ鍵なら、どのファイルでも同じ鍵ストリームと同じ連鎖フラグになる。
2. 鍵ストリームの語は、内部状態（出力）の仮数 32 ビットそのもの。隠れているのは上位 16 ビットだけ。
3. 連鎖するかどうかは鍵ストリームと同じ出力で決まり、平文によらない。
4. 鍵を使うのは最初だけ。§2.1 の値が分かれば、鍵がなくても同じ計算ができる。

## 3. 出発点: 鍵なしで見えていたこと

### 3.1 A・E は同じ鍵ストリームで、連鎖フラグが最上位ビットに出る

A と E を 1 つの鍵で 1 回暗号化したものと考えると、X_n = A_n ⊕ E_n は

```
X_n = PX_n ⊕ f_n·X_{p(n)}        （PX_n = 2 本の平文の XOR）
```

になる。**両方の平文が ASCII（7bit）の区間**では PX の各バイトの最上位ビットが 0 なので、X の最上位ビットには連鎖で足された値だけが見える。連鎖なしの語は 0000、連鎖ありの語は直前の連鎖ありの語と同じ並びになるはずで、フラグ f_n が鍵なしで読める。そう読める区間が 3 か所あった（バイト 0〜117、226〜474、920〜1023。ただし先頭の区間は、レジスタが A・E で同じ IV から始まるので手がかりが出ない）。

実際のデータ（2 つ目の区間の一部。各語の 4 バイトの最上位ビットを左から並べたもの）:

| 語 | X の最上位ビット | 外側のフラグ f | PX の最上位ビット | A と B |
|---|---|---|---|---|
| 62 | 0010 | 0 | 0010 | |
| 63 | 0011 | 1 | 0000 | |
| 64 | 0001 | 1 | 0010 | |
| 65 | 0011 | 1 | 0010 | |
| 66 | 0011 | 1 | 0000 | |
| 67 | 0010 | 0 | 0010 | |
| 68 | 0001 | 1 | 0010 | |
| 69 | 0001 | 1 | 0000 | |
| 70 | 0001 | 1 | 0000 | |
| … | | | | |
| 77 | 0010 | 0 | 0010 | |
| 78 | 0000 | 0 | 0000 | 一致 |
| 79 | 0011 | 1 | 0010 | |

- 4 バイト目の最上位ビットが、そのまま外側の連鎖フラグになっている（この区間では、レジスタの差の最上位ビットが 0001 だった）。
- ところが、連鎖を外した PX の最上位ビットが、全部 0000 にはならない。**3 バイト目だけ、語によって 1 になる。** これを「8bit の列」と呼び、平文のその位置に 8bit の文字があるためと考えていた。

### 3.2 A と B は 20 語だけ一致する

A と B は、256 語のうち 20 語（語 0・2・9・13・43・47・60・78・95・101・110・119・136・169・177・183・214・227・243・244）がそっくり同じで、隣の語は 1 バイトも一致しない。一致する語は、読める範囲ではすべて連鎖なしの語だった。さらに、連鎖なしの語のうち一致するのは「8bit の列の最上位ビットが 0 の語」だけ、という規則が見つかっていた（上の表の語 62・67・77 は連鎖なしだが一致せず、語 78 は一致する）。

### 3.3 行き詰まり

1 つの鍵という前提では、どうしても説明がつかなかった。

- B は「同じ鍵で復号の向きに処理したもの」という読みが消去法で残っていたが、連鎖ありの語で A と B の関係が何も見えない。
- PX（平文の XOR と読んでいた値）が、文章どうしの XOR に見えない。そこで「平文は文章ではない」と考えていた。
- 平文が 7bit という前提で写像の状態を探す探索は、どれも候補 0 だった。

## 4. 着想: 説明のつかない 1 列は、もう 1 層の連鎖フラグ

「8bit の列」を、平文の性質ではなく、**内側にもう 1 回かかっている暗号化（別の鍵 v）の連鎖の跡**と読んでみる。

```
A・E:  平文 M ──(鍵 v で暗号化)──▶ C′ ──(鍵 k で暗号化)──▶ 暗号文
```

このとき、外側の連鎖を外した値は「内側の暗号文どうしの XOR」で、鍵 v の連鎖フラグを f′、直前の連鎖ありの語を p′(n) とすると

```
PX_n = MX_n ⊕ f′_n·PX_{p′(n)}        （MX_n = 本当の平文の XOR）
```

になる。平文が両方 ASCII の区間では MX の最上位ビットが 0 なので、PX の最上位ビットは「内側で連鎖ありの語では、区間に入る前から引き継いだ一定の並び。連鎖なしの語では 0000」になる。その並びがたまたま 1 ビットだけ立っていれば、**1 列だけが、内側の連鎖フラグそのものとして見える**。§3.1 の表の「0010 か 0000 か」は、この形である。

確かめは鍵なしでできる。8bit の列が 1 の語を「内側で連鎖あり」と読み、その語だけ、直前の同じ型の語と XOR して内側の連鎖も外す。仮説が正しければ文章どうしの XOR らしくなり、間違っていれば余計に乱雑になる。

| 区間 | ビット 5 が 0 のバイトの割合（外す前 → 外した後） | 組にする相手をでたらめに変えた 5,000 回 |
|---|---|---|
| バイト 226〜474 のあたり | 53% → 80% | 平均 49%。80% に届いたのは 0 回 |
| バイト 920〜1023 のあたり | 51% → 77% | 平均 51%。77% に届いたのは 0 回 |

（英字どうし、英字と空白の XOR は、ビット 5 が 0 になる。乱数なら 50%。）

これで構造が見えた。同時に §3.2 の規則も読み替えられる。「8bit の列が 0 の語」は「内側の鍵で連鎖なしの語」なので、規則は **「外側でも内側でも連鎖なしの語では A = B」** になる。そういう語では暗号文は 平文 ⊕ K_n ⊕ K′_n なので、B が同じ 2 本の鍵ストリームを使い、平文も A と同じなら、一致して当然である。

（あとで全部が分かってから数えると、平文が両方 ASCII の語 57〜117 の 61 語すべてで、PX の最上位ビットは「内側で連鎖ありなら 0010、なしなら 0000」だった。3 つ目の区間の語 230〜255 でも、26 語すべてで「連鎖ありなら 1000、なしなら 0000」。）

## 5. 2 本の平文と 2 組の連鎖フラグを同時に解く

使うのは X = A ⊕ E だけ。語 n ごとに、2 つのフラグ (f_n, f′_n) の 4 通りと、2 つのレジスタで

```
PX_n = X_n ⊕ f_n·Rout、   f_n = 1 なら Rout ← X_n
MX_n = PX_n ⊕ f′_n·Rin、  f′_n = 1 なら Rin ← PX_n        （最初は Rout = Rin = 0）
```

とすれば、MX_n = M_A ⊕ M_E の語 n が出る。フラグが正しければ MX は「2 本の文章の XOR」になるので、**フラグの列と、MX を 2 本の文章に分ける分け方を、言語モデルの点数でまとめて探す**（ビーム探索）。古典的な「同じ鍵ストリームを 2 回使ったときの解き方」に、語ごとの 4 通りの分岐を足した形である。

- 言語モデルはバイト単位の n-gram。E 側は英文、A 側は英文と Shift_JIS の日本語。材料は、一般の英文と日本語の文書に、ベンダー（IISI）の公開ページと配布物の説明書を足したもの。
- まず英文だけの区間（バイト 226〜474）で 2 本を分けると、E 側に `Features of GCC Chaos Encryption are as follows:` などが出てきた。IISI の英語ページ「GCC Chaos Encryption Overview」（1996-10-20 付）と同じ文である。
- そこで、そのページの文を E 側の手がかり（クリブ）として固定し、最上位ビットの手がかりがない先頭や、日本語の区間まで読み進めた。A 側は、冒頭の英文と、同じ内容の日本語、GCC の説明の英文と続く（§12）。
- 自作の英文 2 本で作った合成では、248 文字中 232 文字が正解になる。
- 最上位ビットから読めていた外側のフラグは、探索が選んだフラグと一致した。
- ここで得たのは、語 0〜131（先頭 528 バイト）の 2 本の平文と、2 組の連鎖フラグ。計算は約 5 分。

この段の読みは言語モデルによるので、まだ「もっともらしい」止まりである。厳密な確かめは §8 で入る。

## 6. B の形を決める

B が「2 つの鍵をどの順序・どの向きで使ったものか」を、鍵なしで判定する。

- B の形の候補を、E_k・D_k・E_v・D_v（鍵 k・v での暗号化・復号の向き）を 1〜3 回重ねた 84 通りとする。
- 候補ごとに、A・B の各語を「鍵ストリームの語 K_n・K′_n、2 つの IV、平文 M_n の XOR」の式として記号で書く。平文と 2 組のフラグは §5 で分かっている。
- **未知数（K・K′・IV）が全部消える A・B の語の組み合わせ**を、GF(2) の掃き出しで全部求める。これが、その形なら鍵なしで成り立つはずの恒等式になる。
- 実データを入れて、成り立つ本数を数える。形が違えば、1 本が偶然に成り立つ確率は 2⁻³²。

| B の形 | 恒等式の数 | 成り立つ数 |
|---|---|---|
| **E_v∘E_k**（k → v の順に暗号化） | 13 | **13** |
| D_k∘D_v（v → k の順に復号の向き） | 13 | **13** |
| D_v∘E_k、D_k∘E_v | 27 | 12 |
| E_v∘D_k、E_k∘D_v | 44 | 12 |
| D_v∘D_k、E_k∘E_v（A と同じ形） | 132 | 12 |
| 同じ鍵を 2 回（E_k∘E_k など 8 通り） | 27〜132 | 0 |

- 恒等式が立つのは 2 層の 16 通りだけ。どの形でも成り立つ 12 本は「A_n = B_n」（一致語）で、残った 2 つの形では、それ以外の 1 本（32 ビットの式）も成り立つ。
- E_v∘E_k と D_k∘D_v は、この方法では区別できない。次の段で決まる。

## 7. 鍵ストリームを 2 本に分ける

A の式だけでは、2 本の鍵ストリームは分けられない。語 n の式には K_n ⊕ K′_n がまとまって入り、連鎖の項を通して別の語の K が混ざるだけで、未知数の半分しか決まらない（E は同じ鍵なので、新しい式にならない）。

**B は鍵の順序が逆なので、連鎖の項に入る相手が違う。** A の式と B の式を連立させると、平文とフラグが分かっている語 0〜131 の範囲で、K_n と K′_n がそれぞれ 118 語ずつ一意に決まった（GF(2) の連立 1 次方程式）。たとえば先頭では、K_0 = A_1 ⊕ B_1（= `cfa907c7`）という、暗号文だけの式になる。

ここで §6 の 2 つの形を区別できる。解いた鍵ストリームが、本当に GCC6 の写像の出力になっているかを見ればよい。写像 1 なら、連続する 3 語から定数が 2 回出る。

```
p = y_n² − y_{n+1} = y_{n+1}² − y_{n+2}        （y = 2x − 1、x は出力）
```

鍵ストリームの語は出力の仮数 32 ビットなので、隠れた上位 16 ビットを全通り仮定すれば、y は 10 桁ほどの精度で分かる。

- E_v∘E_k として解いた K′ は、連続する 3 語の組 95 個すべてで、同じ p = 1.9246476633 を与えた。
- D_k∘D_v として解いた値は、組ごとにばらばらの値しか出ない。

したがって **B = E_v(E_k(M))**。内側の鍵 v は写像 1 と分かった。

```
A・E:  M ──E_v──▶ C′ ──E_k──▶ 暗号文
B:     M ──E_k──▶ G  ──E_v──▶ 暗号文        （A と同じ平文）
```

## 8. 写像の状態を、倍精度で厳密に復元する

鍵ストリームの語が 32 ビットずつ 118 語あるので、情報は余っている。定数と状態を、**DLL と同じ順序の倍精度の計算で、全ビットが合う値**として求める。

### 8.1 鍵 v（写像 1）

- 連続する 3 語について、lo の 65,536 通りと、y・p の上位 48 ビットの候補を当て、y ← y² − p を DLL と同じ丸めで計算して、鍵ストリームの語と全ビットが合うものを探す。
- 見つかった状態から前後に写像を回し、残りの語で確かめる。

### 8.2 鍵 k（写像 2）

外側の鍵 k は写像 2 だった。未知数が多い（Q・A と、出力に出ない u）ので、近似から入る。

- w_n = v_{n+1} − C·v_n = Q·u_n² と置くと、w_{n+1} = w_n·(A − Q·v_n)²。C = 1 − Q を使うと、連続する 4 語の出力だけから

```
± √(w_1/w_0) ∓ √(w_2/w_1) = Q·(v_1 − v_0)        （w_n = (v_{n+1} − v_n) + Q·v_n）
```

  という Q だけの式になる。これを解いて Q、続けて A = Q·v_0 ± √(w_1/w_0) を出す。隠れた上位 16 ビットは全通り試し、先の語を予測して鍵ストリームと比べる。
- 近似解（Q ≈ 0.8405、A ≈ 1.8085）のまわりで、lo の 65,536 通りと、Q・A・C・u の上位 48 ビットの候補を全部試し、分かっている語が全部合うものを出す。ここが全体でいちばん重く、十数分かかった。

### 8.3 副産物: 平文の読み違いが見つかる

厳密な照合は、1 ビットの違いも許さない。最初、鍵 v で 1 語、鍵 k で 1 語だけ合わない語が残った。どちらも鍵ストリームの 1 バイトのずれで、たどると §5 の言語モデルの読みが違っていた。

- バイト 335: A の `chaos` の `c` と、E の `Multimedia` の `M`（大文字と小文字を逆に読んでいた）。
- バイト 345: A の `has` の `h` と、E の `Multimedia.` の `.`。

直すと、**解いた鍵ストリーム 118 語 × 2 本（3,776 ビットずつ）が、写像の出力と全ビット一致した。** この時点で、§5 の読み（語 0〜131）と §4〜§7 の構造は、統計ではなく厳密な一致で確かめられたことになる。

### 8.4 lo は 1 つに決まらない

どちらの鍵でも、lo はある範囲のどれでも同じ鍵ストリームになる（下位 16 ビットが上位 48 ビットに響くのは、丸めで桁が上がるときだけなので）。最後まで残る幅は、k で 44 通り、v で 183 通り。復号には影響しない。

## 9. 先頭 1,024 バイトの復号と、確かめ

- 状態を語 0 まで逆向きに戻し、語 255 まで前に回して、2 本の鍵ストリームと連鎖フラグを全部出す。写像 2 を 1 歩戻すには、u についての 3 次方程式 Q²u³ + (A·C − Q·v′)·u − C·u′ = 0 を解き、根のまわりで厳密に合う点を探す。
- 2 つの IV は状態からは出ないので、先頭 2 語の平文（A は `Is t`・`rue?`）から逆算する。先頭の語で鍵なしに決まるのは A と E の平文の XOR（`01 1a 0c 79`）だけで、A の `Is t`、E の `Hi,` と改行は読みである。A では同じ文がバイト 871 からもう一度出るので、読みは確かだとみてよい。
- これで A・E の先頭 1,024 バイトが復号できる。語 132 以降の平文は、ここで初めて出たもので、言語モデルの読みは入っていない。
- 決め手の確かめ: **A の平文を k → v の順に暗号化し直すと、実物の B と 256 語（1,024 バイト）全部が一致する。**
- 「両方の鍵で連鎖なし」の語は 19 個で、A = B の 20 語から語 0 を除いたものと過不足なく一致する。語 0 は、連鎖があっても足されるのが共通の IV なので一致する。

## 10. 空回しの前の初期値まで戻る

§9 までで分かったのは「語 0 以降の状態」である。E は 1,338 バイトあり、1,024 バイト目で写像が**初期値から**作り直される（§2.5）。残りの 314 バイトを復号するには、空回しの前の初期値が要る。

### 10.1 鍵 v（写像 1）を逆向きにたどる

y ← y² − p の逆は y = ±√(y′ + p) で、符号の 2 通りに分かれる。倍精度の格子（下位 16 ビットが lo の数）の上で、**1 歩進めると厳密に y′ になる点**を全部求める。y² − p は |y| について単調なので、符号ごとに原像は連続した区間になり、両端だけ厳密に決めれば足りる。

- 語 1 の状態から語 0 の状態に戻ると、候補は 1 つに決まらなかった。符号が 2 通りあるうえ、語 0 の状態がたまたま小さく（|y| ≈ 0.028）、写像がそこで縮むので、符号ごとに約 1,150 個の格子点が同じ次の状態に落ちる。語 0 の鍵ストリームの値にして 58 通りになる。
- ここで鍵スケジュールの決まりが効く。**語 0 の鍵ストリームの候補ごとに IV が決まり、IV（= S）が決まれば空回しの回数（S mod 79）が決まる。** 候補ごとに、その回数だけ厳密にさかのぼれるかを調べた。
- 最後までさかのぼれたのは 1 通りだけだった: y_0 = −0.027765、語 0 の鍵ストリーム `8c8c921c`、IV_v = `81 34 9d 3a`、空回し 23 回、初期値 y = ±0.600366347314。ほかの 57 通りは、どの lo でも途中で原像がなくなる。正しくない点から逆向きにたどると、十数歩で行き止まりになる。
- この逆向きの探索は、乱数の鍵 400 本で、真の初期値が必ず候補に入ることを確かめてある。

なお、ここで語 0 の状態の符号が、それまで仮に置いていたもの（正）と逆だと分かり、IV_v の値が変わった。語 0 の鍵ストリームと IV の XOR は同じなので、§9 の復号結果は変わらない。

### 10.2 E の 2 ブロック目

- 鍵 v の層は、初期値と、作り直したあとの定数 p′ から、2 ブロック目の鍵ストリームが出る。p′ は、k7b0 のバイト 5 を置き換えて計算する。k7b0 は p から 10 桁ほどしか分からないので、p′ の上位 48 ビットには ±1 の幅が残るが、候補として全部試せばよい。
- 鍵 k の層は、この時点では初期値が分からない。そこで**平文の予想**を使った。E の 1 ブロック目は、前に出てきた段落をもう一度書いている途中（`Features` の `Fea`）で終わっている。続きは `tures of GCC Chaos Encryption are as follows:` と特長 7 項目だと予想できる（268 バイト）。
  - 予想した平文に鍵 v の層を掛け、暗号文と XOR すれば、鍵 k の鍵ストリームの語（に連鎖の項が付いたもの）が出る。
  - 連続する語が、作り直したあとの定数 Q′・A′・C′ での写像 2 の式（§8.2）に合うかを見る。鍵ストリームに出ない上位 16 ビットは、語ごとに 200 通りの仮説を全部試す。
  - 合う仮説は 1 通りで、続く 4 語（24 ビットずつ）がすべて合った。同じ検査を 1 ブロック目の 4 か所で行うと、どこでも正解の 1 通りだけが残る。
- そのあと状態と定数を倍精度で決めると、**予想した 67 語（2,144 ビット）の鍵ストリームがすべて一致した。**
- 予想していなかった残り 46 バイトは、空行と署名 `1996/11/16  Gao Zhenyu, Ph.D. JAPEN` になった。日付は E のファイルの日付と同じである。
- 末尾の端数 2 バイト（§2.5 の別の式で、2 つの IV の 2 バイト目を使う）は CR LF になった。§10.1 で決め直した IV_v の確かめにもなっている。

### 10.3 鍵 k（写像 2）の初期値

鍵 k の 2 ブロック目の最初の状態は、「初期値から、作り直した定数で 1 歩進めたもの」である。この 1 歩を逆に解く（§9 と同じ 3 次方程式）と、初期値 (k780, k788) = (0.656269299244, 0.654832310109) が出る。

これを 1 ブロック目の定数で 70 歩（空回し 69 回 = S_k mod 79 と、語 0 を出す 1 歩）進めると、**§8 で復元した語 0 の状態にちょうど着いた。** lo の 44 通りのどれでも同じ。別々に求めた 2 つのブロックの状態が、鍵スケジュールの決まり（IV と空回しの回数）でつながったことになる。

### 10.4 鍵スケジュールの出力としてまとめる

ここまでの値を、鍵ごとに 1 組の倍精度の数（mode、k780、k788、k7b0、k7b8、S、lo）にまとめた。k7b0・k7b8 は、1 ブロック目と 2 ブロック目の定数の上位 48 ビットを両方再現する値を、近似値のまわりで探して選ぶ。

[`src/verify.py`](../src/verify.py) は、この値だけを持ち、DLL の処理（定数の計算、空回し、鍵ストリーム、連鎖、1,024 バイトごとの作り直し、端数）を最初からなぞる。3 本が全バイト復号でき、B が作り直せる。

## 14. なぜ解けたか（暗号の側の弱点）

1. **鍵ストリームの使い回し。** ナンスがないので、同じ鍵で暗号化した A と E の XOR から鍵ストリームが消える。二重にしても、2 本とも同じ鍵の組なら同じことが起きる。
2. **連鎖フラグが漏れる。** 連鎖するかどうかが出力の値だけで決まり、平文が ASCII の区間では、暗号文の XOR の最上位ビットにそのまま出る。内側の層のフラグまで見えた。
3. **順序を入れ替えた暗号文があった。** 同じ平文を、同じ 2 本の鍵で順序だけ変えて暗号化した B があったので、2 本の鍵ストリームが 1 次方程式で分かれた。A と E だけなら、2 本の XOR までしか分からない。
4. **鍵ストリームが内部状態そのもの。** 語は出力の仮数 32 ビットで、下位 16 ビットは固定、隠れているのは上位 16 ビットだけ。数語の鍵ストリームから、写像の定数と状態が倍精度の値として決まる。
5. **状態が分かれば、鍵は要らない。** 鍵を使うのは最初の計算だけで、あとは決まった計算が続く。1,024 バイトごとの作り直しも、初期値と暗号文の 1 バイトで決まる。
6. **空回しは守りにならない。** 写像は逆向きにもたどれて、正しくない枝はすぐ行き止まりになる。空回しの回数が IV から決まることが、かえって候補を 1 つに絞る条件になった。
7. **平文が推測しやすかった。** 公開ページと同じ文、同じ段落の繰り返しがあり、クリブと 2 ブロック目の予想に使えた。

---

## 15. 遠回りの記録

- **「1 つの鍵で 1 回」という前提。** これを置いたまま、平文どうしの XOR（のつもりの値）が文章らしくないことから「平文は文章ではない」と読み、B の一致語の少なさから「B は復号の向き」と読んでいた。どちらも、内側の層を見落としていたための読み違いだった。
- **7bit の前提での状態探索。** 外側の鍵から見た入力は内側の暗号文で、乱数に見える。平文が 7bit という条件は外側の層では成り立たないので、正しい状態を必ず落としていた。候補 0 の結果は、鍵について何も言っていなかった。
- **合っていたもの。** 最上位ビットから読んだ外側の連鎖フラグ（途中で 2 語を訂正した版）、外側の鍵が写像 2 であること、フラグだけから絞った定数の範囲（真の値はその中にあった）。これらは二重暗号化でも外側の層についてそのまま成り立つ。
- **抜け出したきっかけ。** 説明のつかない観測（1 列だけの最上位ビット、連鎖なしの語の一部だけが一致する規則）を「平文の性質」で済ませず、「暗号の側にもう 1 つ仕掛けがある」と読み替えたこと。鍵なしで数えられる検査（§4 の表）にできたので、すぐ白黒がついた。
